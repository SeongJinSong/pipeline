# 계획과 결정 기록

PR 설명은 병합 후 잘 보지 않습니다. **왜 이렇게 만들었는지의 원본은 이 폴더**이고, PR 설명은 요약과 이 문서 링크만 둡니다.
사람도 에이전트도 작업 전에 관련 문서를 읽고, 이미 버린 대안을 근거 없이 다시 시도하지 않습니다.

## 규칙

- PR 하나에 문서 하나: `issue-<이슈번호>-<주제>.md`. 이슈가 없으면 `change-<번호>-<주제>.md`.
- 구현 전에 쓰고 같은 PR에 커밋합니다. 같은 PR에 이어서 수정하면 같은 문서의 "변경 기록"에 덧붙입니다.
- 병합 후 결정을 뒤집을 때는 기존 문서를 고치지 않고 새 문서를 만들어 서로 링크합니다.
- 비밀값(키, 토큰), 개인정보, DB 덤프는 적지 않습니다.
- 형식은 [TEMPLATE.md](TEMPLATE.md)를 따릅니다. Slack에서 요청하면 파이프라인이 이 형식으로 문서를 만들고 에이전트가 채웁니다.
